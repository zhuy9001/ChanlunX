# 缠论功能梳理 PRD（PDF 来源版）

版本：v0.2
来源：`docs/pdf/cl.pdf`
说明：本文仅根据 PDF 内容梳理功能点，不参考任何现有程序实现。页码为 PDF 文本抽取页码，可能与印刷页码不完全一致。

## 1. 目标

从 PDF 中抽取缠论体系可产品化的功能模块，形成后续软件实现、指标开发、可视化设计和测试验收的需求基线。

本 PRD 的核心目标不是描述某个既有程序如何实现，而是回答：

- 缠论分析系统应该具备哪些功能？
- 每个功能需要识别什么结构？
- 这些结构之间如何递进？
- 哪些功能属于基础能力，哪些属于增强能力？

## 2. 功能总览

从 PDF 梳理出的功能可分为九组：

1. 行情基础处理：K 线、包含关系、非包含化。
2. 基础几何结构：分型、笔、线段。
3. 中枢体系：中枢识别、中枢区间、中枢延伸、扩展、新生。
4. 走势体系：走势、走势类型、盘整、趋势、走势终完美。
5. 级别体系：最低级别、递归定义、多级别联立。
6. 买卖点体系：第一类、第二类、第三类买卖点和卖点。
7. 背驰体系：趋势背驰、盘整背驰、MACD 辅助判断。
8. 分解体系：同级别分解、走势连接、区间套。
9. 操作辅助：持股持币、短差、风险退出、节奏管理。

## 3. 基础行情处理

### F1. K 线数据读取

功能描述：

- 支持读取某个交易品种在某一周期下的 K 线序列。
- K 线至少需要包含高点、低点和时间顺序。
- 分析结果必须基于已经走出的 K 线，不能依赖未来数据。

需求依据：

- PDF 多处强调“当下性”，即结构确认依赖已经走出的图形。参考 p758。

验收标准：

- 输入 K 线按时间顺序排列。
- 当 K 线数量不足以形成后续结构时，不输出结构结论。
- 同一份已完成 K 线数据重复分析，结果应一致。

### F2. K 线包含关系处理

功能描述：

- 识别相邻 K 线的包含关系。
- 向上时，将包含 K 线组合并为高点较高、低点较高的新 K 线。
- 向下时，将包含 K 线组合并为低点较低、高点较低的新 K 线。
- 连续包含必须按顺序处理，不能把包含关系当作可传递关系。

需求依据：

- PDF p740 描述向上、向下时的包含合并方法。
- PDF p757 强调包含关系不符合传递律，必须遵守顺序原则。

验收标准：

- 处理后的 K 线序列应消除相邻包含关系。
- 连续包含时，先合并前两根，再与后一根比较。
- 保留合并前后的索引映射，便于后续结构定位。

## 4. 基础几何结构

### F3. 分型识别

功能描述：

- 在非包含 K 线序列中识别顶分型和底分型。
- 顶分型用于标记潜在顶部结构。
- 底分型用于标记潜在底部结构。

规则摘要：

- 顶分型：中间 K 线高点为相邻三根中最高，低点也为相邻三根中最高。
- 底分型：中间 K 线低点为相邻三根中最低，高点也为相邻三根中最低。
- 顶分型取其最高点作为“顶”，底分型取其最低点作为“底”。

需求依据：

- PDF p740 给出顶分型、底分型和顶底含义。
- PDF p758 强调分型结果应在图形已走出后按统一标准确认。

验收标准：

- 非包含化前不直接确认分型。
- 同一有效位置不能同时输出顶分型和底分型。
- 已确认分型可映射回原始 K 线位置。

### F4. 笔识别

功能描述：

- 由相邻顶、底分型构造笔。
- 向上一笔由底到顶构成。
- 向下一笔由顶到底构成。
- 所有有效笔应上下交替连接。

规则摘要：

- 顶和底必须相邻，隔多个顶底不能直接视为一笔。
- 顶底之间至少应存在一根独立 K 线，避免共用 K 线。
- 相邻异类分型只有同时满足独立 K 线间距、顶高于底的价格关系，以及端点覆盖起止区间内全部标准 K 线的最高价和最低价，才构成候选反向笔；单个反向分型不足以确认原笔终结。
- 两个连续同类分型之间若没有有效反向分型，应按极值更新候选，而不是强行成笔。
- 笔的端点先作为候选；从该端点出发的反向笔也满足上述成笔条件时，原候选笔暂时确认。确认不是不可撤销的历史锁定：只有发生下述端点替换并导致重新校验失败时，才可逐级使既有笔失效。仅有反向分型或不合格的反向笔时，原笔仍可延伸。
- 若候选反向笔不能成立，继续寻找同向更极端的分型，更新原笔终点；中间的短转折不单独画成笔。
- 后续出现更极端的同类分型时，先检查它与其间的异类分型能否构成有效笔。若不能，撤销该中间转折，以新分型替换较早的同类端点，再按时间顺序重新校验受影响笔的独立 K 线间距、顶底价格关系和整段标准 K 线极值覆盖。
- 若替换后的前一笔也不满足成笔条件，继续逐级回退并重新验算；只在重新校验仍有效的连续笔处停止。已暂时确认的笔也可能因该因果链失效，但不得仅凭更晚的新高、新低，或按全局笔数、固定回退笔数删除中间笔；未受影响的有效前缀应保持不变。
- 端点替换的影响范围只到产生替换的尾部候选链：先保留替换点之前已经满足成笔条件、且不依赖被替换端点的有效前缀；仅从被替换端点及其直接相邻的未确认尾部开始重新验算。后续更极端分型不能跨过有效前缀重新选择更早端点。
- 待定尾部极值不得成为永久阻塞状态。每出现新分型，应重新尝试与当前尾端成笔、同类极值延伸及受影响尾部的逐级回退；若新的区间极值使尾端旧笔失效，应重选局部端点并继续扫描，未受影响的前缀不变。未满足成笔条件时可暂不画新笔，但不能因待定状态忽略所有后续分型。
- 例如 300383 的 2026-06-25 顶之后，06-30 出现比 06-11 底更低的标准 K 线低点，07-01 又出现更高顶；若两次相邻分型间距不足以构成有效反向笔，06-11 至 06-25 的尾部上升笔可在重算时失效。不得为了保留旧画线跳过 06-30 的区间极值，也不得跳过受影响的端点覆盖检查。
- 首笔建立后若后续连续转折均不能从当前起始锚点接续，应保留短转折中的极值候选，并按相同的间距、价格和整段覆盖条件重新选择起始锚点；允许受影响的首笔调整，不得把首笔位置永久锁定。禁止为了持续出笔而连接不合格端点。
- 笔识别统一使用标准 K 线上的间距、顶底价格关系和整段极值覆盖校验；正常扫描、同类端点替换和尾部回退不得使用不同的成笔口径。状态须区分可保留的连续有效前缀、可重算的尾部笔和尚未成笔的候选分型。每次新区间极值只重算直接受影响的尾部，遇到仍有效的连续笔即停止；不得以更晚终点或更多笔数为由删除未失效的中间笔。
- 局部回退时保留受影响尾部的分型候选；后续分型能从该尾部形成有效反向笔时，恢复前须重新校验保存链的全部相邻笔，并保留共同有效前缀。不得用全局路径笔数选择替代此判定。尾部仅含一条已确认笔及其候选反向笔时，短距更极端分型先进入待定，不直接删除唯一已确认前缀。
- 加载窗口的左边界不能伪造三根分型；不同窗口共同覆盖的充分后续区间，已确认笔应保持一致。缩短历史可以改变最早尚未确认的笔，不得导致中后段整段停笔；上市未满一年的股票同样按实际可用标准 K 线判定，不设置最低交易年限。
- 笔的分型、端点价格及整段极值覆盖均以顺序包含处理后的标准 K 线为准；原始 K 线索引用于将分型位置映射回图表，不以合并时舍弃的原始高低价否定笔。例：300652 的 2024-08-29 与 08-30 沿此前上升方向合并为高 18.48、低 16.77，08-30 原始低点 16.34 不参与这根标准 K 线的笔极值校验。
- 例：000801 在 2026-04-30 的候选底到 2026-05-11 的更高顶不足以成反向笔；以 05-11 顶替换 04-21 顶后，04-30 的底又低于 03-30 的底，须按上述条件逐级重新校验，目标是使 02-25 的下降候选延伸到 06-26 的新低。不能仅因 05-11 创新高跳过中间笔；后续不能成笔时，不强制把不连续的端点连接。

需求依据：

- PDF p740 说明相邻顶底构成笔，并强调顶底之间至少需要一根 K 线。
- PDF p758 说明图形可分解为上下交替的笔连接。

验收标准：

- 输出笔的方向、起点、终点、覆盖 K 线范围。
- 笔序列必须顶底交替。
- 不满足独立 K 线要求时，不确认有效笔。
- 连续回退后仍须保证每笔的起止分型不共用 K 线、端点覆盖笔区间极值，相邻笔共享端点；未确认的尾部反向分型不截断当前笔。
- 有效反向笔暂时确认后，后续新极值本身不得删除它；仅当中间反向笔不成立、同类端点被更极端分型替换，且重新校验使该笔失效时，才允许逐级撤销。无效尾部转折不得造成停笔，未失效的中间笔不得被吞并。
- 回归 000801 的上述逐级失效与延伸场景、300652 的中间笔重新校验场景，以及不同历史加载窗口中未受失效链影响的端点一致性；历史样例的具体笔序须按同一套规则重算，不以固定笔数或固定端点作为优先于规则的例外。
- 300652 的 2024-06-19、07-05、07-12、07-25、08-01、08-28 相邻转折按统一间距和标准 K 线极值覆盖逐笔验收；合格中间笔不得强制合并成 06-19 至 08-28 一笔。旧测试日期预期不能优先于统一规则。
- 回归 300383：2025-12-17 -> 2026-01-14 与 2026-01-14 -> 2026-01-21 已成笔时，后续 2026-01-26、2026-02-03 等更高顶只能重算其后的尾部，不能吞掉这两笔有效前缀。
- 完整历史回归还须覆盖 300383 在 2026-06-25 之后、603360 在 2025-12-05 之后、000028 在 2026-06-18 之后、000034 在 2026-02-27 之后的待定尾部退出；000025 应在 2025-04-07 之后继续产生有效笔。分别验证端点交替、连续、间距及区间极值覆盖，不能只以笔数非零判定通过。
- 回归 001316：保留 2025-10-20 至 12-01 期间按统一条件成立的中间笔；12-01 顶、12-17 底、2026-02-05 顶的有效反向笔不得被更晚极值吞并，不要求 10-20 底直接连接 12-01 顶。回归 000975 的多个实际标准分型端点，不把原始 K 线日期直接当成合并后的分型；000883、000885 比较不同加载窗口的共同后续笔序；001220 验证首年新股仍能在具备合格分型时持续成笔。000559 在本地未复现停笔，需同时检查数据口径和实际 DLL 版本。

### F5. 线段识别

功能描述：

- 在线段层面聚合多笔结构。
- 线段至少由三笔构成。
- 线段用于进一步构造最低级别中枢和走势类型。

规则摘要：

- 连续三笔不一定必然构成线段，前三笔必须存在重叠部分。
- 向上笔开始的线段，需要考察下行笔组成的特征序列。
- 向下笔开始的线段，需要考察上行笔组成的特征序列。
- 特征序列需要进行非包含化，形成标准特征序列。
- 线段结束以标准特征序列出现相应分型为前提。

需求依据：

- PDF p759 说明线段至少三笔、前三笔需要重叠，以及线段破坏条件。
- PDF p767-p768 说明特征序列、缺口、标准特征序列和线段划分标准。

验收标准：

- 未满三笔不输出线段。
- 三笔无重叠不输出线段。
- 标准特征序列分型未出现时，不确认线段结束。
- 线段结果可作为更高级结构的输入。

## 5. 中枢体系

### F6. 中枢识别

功能描述：

- 识别某级别走势中由至少三个连续、同级别、已完成的次级别走势类型重叠形成的中枢。
- 中枢是后续判断盘整、趋势、买卖点、背驰的核心结构。

规则摘要：

- 中枢的构成单位是三个连续、同级别、已完成的次级别走势类型，不得把任意三个价格区间或三个未完成候选直接确认为中枢。
- 构成单位必须按时间顺序连接；前一单位的结束位置应与后一单位的开始位置一致，或由明确的级别连接规则连接。
- 若三个构成单位的高低点分别为 `[a2,a1]`、`[b2,b1]`、`[c2,c1]`，其中低点小于等于高点，则中枢区间为 `[ZD,ZG]`：`ZD=max(a2,b2,c2)`，`ZG=min(a1,b1,c1)`。
- `ZD <= ZG` 时才存在重叠并形成中枢；边界相等属于有效重叠。
- 中枢方向取与中枢形成方向一致的次级别走势方向；方向不能替代中枢区间和级别定义。
- 对于最低不可分解级别，可按项目配置使用至少三根连续单位 K 线的重叠部分定义最小中枢；该规则不能替代更高级别的递归构造。
- 中枢记录构成单位列表、起止位置、所属级别、`ZD/ZG`、`GG/DD` 和确认状态。

需求依据：

- PDF p120、p126、p128 给出走势类型中枢的定义和区间计算。
- PDF p129、p150-p155 区分中枢延伸、同级别新生中枢和更高级别中枢扩张。
- PDF p115、p412、p428 说明中枢定义的递归起点和最低级别处理。

验收标准：

- 少于三个连续、同级别、已完成的次级别走势类型不确认中枢。
- 构成单位不连续、级别不一致或仍为候选状态时不确认中枢。
- `ZD > ZG` 时不确认中枢；`ZD == ZG` 时确认边界重叠中枢。
- 同一延伸中枢不得因滑动窗口重复生成多个独立中枢。
- 中枢应输出构成单位、`ZD/ZG`、起止位置、所属级别、方向和确认状态。
- 同一份截至某根 K 线的数据重复计算，历史已确认中枢的结果必须稳定。

### F7. 中枢指标

功能描述：

- 计算中枢相关的高低区间和运行边界。

建议指标：

- `ZG`：中枢上沿。
- `ZD`：中枢下沿。
- `GG`：中枢及其延伸中所有相关次级别走势类型高点 `gn` 的最大值。
- `DD`：中枢及其延伸中所有相关次级别走势类型低点 `dn` 的最小值。
- `G/D`：可选的中枢内部运行边界，必须与 `GG/DD` 的统计范围区分。
- `Center`：中枢中心，可按项目实现定义为 `(ZG + ZD) / 2`。

需求依据：

- PDF p154-p155 对 `ZG/ZD/GG/DD` 及中枢中心定理进行说明。

验收标准：

- 中枢区间满足 `ZD <= ZG`。
- 初始中枢确认后，`ZG/ZD` 表示该中枢的重叠区间；延伸期间不得因新增重叠单位随意改变初始区间。
- 中枢延伸时，`GG/DD`、结束位置和构成单位列表动态更新；若项目采用候选状态，也必须同步更新状态和确认时点。
- `GG/DD` 的统计范围必须覆盖中枢构成单位及已经纳入延伸的单位，不能只统计三段窗口的极值。
- 指标可用于后续第三类买卖点、趋势延续和高级别中枢判断，并能追溯所属中枢及级别。

### F8. 中枢延伸、扩展、新生

功能描述：

- 识别中枢后续走势属于延伸、扩展还是新生。

规则摘要：

- **延伸**：后续同级别次级别走势继续围绕原中枢运行，且其波动区间与原中枢 `[ZD,ZG]` 保持规定的重叠关系；延伸属于原中枢，不生成新的同级别中枢。
- 中枢延伸至少应记录：原中枢 ID、纳入的后续构成单位、最新结束位置、`GG/DD` 和延伸状态。
- **新生**：原中枢结束后，后续三个连续、同级别、已完成的次级别走势类型形成新的重叠区间，并且该区间不与前一同级别中枢重叠，才形成新的同级别中枢。
- 同级别前后中枢区间重叠时，不得直接判定为趋势中的两个独立中枢；应进入延伸或高级别中枢候选判断。
- **扩展/高级别中枢**：不是简单把两个重叠中枢合并。应以围绕中枢的次级别波动区间为输入，判断新中枢产生前后波动是否与既有中枢相关波动重叠，并在更高级别递归层形成中枢候选。
- 需要区分“中枢区间 `[ZD,ZG]` 重叠”和“围绕中枢的波动区间重叠”；前者可能表示同级别中枢不能分离，后者才可能触发高级别中枢构造。
- 中枢离开后，只有第一次回试或回抽满足相应边界条件时，才能为第三类买卖点提供已确认中枢依据；后续回试不能重复标记为第一次回试。
- 中枢状态至少包括：`Candidate`（候选）、`Confirmed`（已确认）、`Extending`（延伸中）、`Terminated`（已终结）、`Invalid`（失效）。
- 笔级几何中枢的输入笔须共享索引和端点价格、方向交替且已确认。已确认反向回试严格在区间外时终结；边界接触算重叠，候选回试不提供终结证据。内部保存构成笔索引及反向笔的确认依据位置，精确分型确认时刻须另行记录，不能把端点时间误称实时确认时刻。
- 后续与前一中枢重叠的结构保留为关联候选，不直接丢弃，不作为独立已确认方框输出，也不冒充已实现的高级别递归中枢。

需求依据：

- PDF p129 描述盘整和趋势中的走势类型延伸。
- PDF p150-p155 说明同级别中枢不能重叠、围绕中枢的波动重叠可产生更高级别中枢，以及中心定理。
- PDF p180、p189、p235 多次强调中枢有延续、扩展、新生三种运动。

验收标准：

- 后续走势与原中枢有规定的重叠时，延长原中枢并更新 `GG/DD`，不生成重复滑窗中枢。
- 后续走势有效离开原中枢后，原中枢进入 `Terminated`；离开条件必须使用已完成的次级别走势确认，不能仅由单根 K 线越界确认。
- 新的同级别中枢必须由三个连续、同级别、已完成的次级别走势类型构成，且与前一同级别中枢不重叠，才可作为趋势延续候选。
- 前后同级别中枢区间绝对不重叠时，才可进入同级别趋势延续判断。
- 出现围绕中枢的波动区间重叠时，应进入高级别中枢候选，而不是直接确认趋势或新生同级别中枢。
- 能区分延伸、同级别新生和高级别扩展，并为每种状态输出可追溯的构成依据。

## 6. 走势体系

### F9. 走势类型识别

功能描述：

- 将走势划分为盘整、上涨、下跌三类。

规则摘要：

- 走势类型包括上涨、下跌、盘整。
- 盘整：某完成走势类型只包含一个中枢。
- 趋势：某完成走势类型至少包含两个以上依次同向的中枢。
- 趋势方向向上称为上涨，向下称为下跌。
- 趋势中的同级别中枢之间必须不存在重叠。

需求依据：

- PDF p123、p128 给出走势类型、盘整、趋势定义。
- PDF p127 强调趋势中的中枢之间不能重叠。

验收标准：

- 一个中枢只能确认盘整候选，不能直接确认趋势。
- 两个以上同向且不重叠中枢才确认趋势。
- 同级别中枢重叠时，转入高级别中枢判断。

### F10. 走势终完美

功能描述：

- 判断任意级别走势类型是否已具备完成条件。
- 给用户提示当前走势是已完成、可随时完成，还是仍处于延伸。

规则摘要：

- 任何级别的任何走势类型终要完成。
- 任何完成的走势类型至少包含一个中枢。
- 盘整可在一个中枢后完成，也可继续延伸。
- 趋势可在两个同向中枢后完成，也可继续延伸。

需求依据：

- PDF p123、p128 给出基本原理。
- PDF p129 讨论盘整和趋势延伸导致的完成判断难点。

验收标准：

- 输出走势完成状态：未形成、形成中、可完成、已完成、延伸中。
- 不把“可完成”误标为“必然反转”。
- 当前走势继续产生中枢时，应更新延伸状态。

## 7. 级别体系

### F11. 最低级别设置

功能描述：

- 支持指定分析的最低级别，例如 1 分钟、5 分钟或更细粒度。
- 在最低级别上，用单位 K 线重叠来定义最小中枢。

需求依据：

- PDF p115 指出实际操作中可设定最低不可分解级别。
- PDF p742 说明可从 1 分钟或其他基础图形开始定义分型、笔、线段、中枢和走势类型。

验收标准：

- 用户能指定最低分析级别。
- 最低级别定义不影响更高级别递归规则。
- 不混淆“使用什么周期图”和“实际走势级别”。

### F12. 级别递归

功能描述：

- 从最低级别结构递归生成更高级别中枢和走势类型。
- 支持跨级别观察同一走势。

规则摘要：

- 最低级别中枢形成最低级别走势类型。
- 低级别走势类型的连接与重叠可构造更高级别中枢。
- 级别分析应从高级别到低级别综合判断，避免只盯小级别。

需求依据：

- PDF p115、p412、p428 说明中枢和走势类型的递归定义。
- PDF p124、p742 说明不同周期图与走势级别不是同一概念。

验收标准：

- 同一走势可输出多个级别的结构标签。
- 高级别结构与低级别结构之间保留父子关系。
- 第二类买点、区间套等跨级别功能能调用递归结果。

## 8. 买卖点体系

### F13. 第一类买卖点

功能描述：

- 识别由背驰导致的趋势转折买卖机会。

规则摘要：

- 第一类买点通常对应下跌走势背驰后的转折。
- 第一类卖点通常对应上涨走势背驰后的转折。
- 均线系统早期描述中，第一类买点可理解为下跌末端背驰结构；后续应以中枢和走势结构为主。

需求依据：

- PDF p70-p72、p82-p85 说明第一类买卖点与背驰、MACD 辅助关系。

验收标准：

- 未形成可比较的走势段时，不输出第一类买卖点。
- 背驰条件不成立时，不输出第一类买卖点。
- 输出买卖点必须标明所属级别。

### F14. 第二类买卖点

功能描述：

- 识别第一类买卖点后，走势回抽确认形成的二类机会。

规则摘要：

- 大级别第二类买点可由次级别对应走势的第一类买点构成。
- 第二类买点用于提高入场精度。
- 第二类卖点与买点逻辑对称。

需求依据：

- PDF p82-p86 说明第二类买点和“大级别第二类买点由次级别第一类买点构成”的关系。

验收标准：

- 必须存在前序第一类买卖点或对应转折结构。
- 必须支持调用次级别结构进行确认。
- 输出级别、触发位置和确认依据。

### F15. 第三类买卖点

功能描述：

- 识别中枢离开后的首次回抽确认机会。

规则摘要：

- 第三类买点：次级别走势向上离开中枢后，以次级别走势回试，其低点不跌破中枢上沿。
- 第三类卖点：次级别走势向下离开中枢后，以次级别走势回抽，其高点不升破中枢下沿。
- 必须是离开中枢后的第一次回试或回抽。
- 第三类买卖点后可能趋势延续，也可能进入更大级别盘整。

需求依据：

- PDF p150-p152 给出第三类买卖点定理和注意事项。

验收标准：

- 没有已确认中枢时，不输出第三类买卖点。
- 回试或回抽重新进入中枢区间时，不输出第三类买卖点。
- 非第一次回试或回抽不标记为标准第三类买卖点。

## 9. 背驰体系

### F16. 背驰识别

功能描述：

- 对同级别、同方向的走势段进行力度比较，识别背驰。
- 背驰用于辅助第一类买卖点、走势转折和风险提示。

需求依据：

- PDF p70-p72、p82-p85 说明买卖点与背驰关系。
- PDF 目录中包含“没有趋势，没有背驰”“MACD 指标对背驰的辅助判断”“背驰的再分辨”等章节。

验收标准：

- 没有趋势或可比较走势段时，不输出趋势背驰。
- 背驰信号必须绑定级别、方向和比较对象。
- 支持标记背驰已确认、背驰候选、背驰失败。

### F17. MACD 辅助判断

功能描述：

- 使用 MACD 红绿柱、黄白线、面积或高度等指标辅助判断背驰。

需求依据：

- PDF p82-p85 多次用 MACD 绿柱缩短、红柱未创新高辅助说明背驰。
- PDF p87 提到 MACD 参数周期会影响判断。

验收标准：

- MACD 仅作为辅助，不替代走势结构判断。
- 支持配置 MACD 参数。
- 输出辅助依据，例如柱面积缩小、柱高缩小、黄白线未创新高或新低。

### F18. 盘整背驰

功能描述：

- 识别盘整走势内部的力度衰竭。
- 区分盘整背驰和趋势背驰。

需求依据：

- PDF 目录中包含“盘整背驰与历史性底部”“背驰的再分辨”等章节。
- PDF 多处提醒需要区分背驰与盘整背驰。

验收标准：

- 当前走势未形成趋势时，不把盘整背驰误判为趋势背驰。
- 盘整背驰输出应提示其转化为第三类买卖点或继续盘整的可能。

## 10. 分解体系

### F19. 同级别分解

功能描述：

- 将任何级别走势分解为同级别盘整、上涨、下跌的连接。

需求依据：

- PDF p123、p128 给出走势分解定理。
- PDF 目录包含“走势类型连接的同级别分解”“同级别分解再研究”等章节。

验收标准：

- 输出分解后的走势类型序列。
- 每个走势类型包含起点、终点、级别和类型。
- 相邻走势类型的连接关系清晰，不出现重叠归属混乱。

### F20. 区间套

功能描述：

- 通过逐级降低分析级别，定位更精确的买卖点。

需求依据：

- PDF 目录包含“区间套定位标准”。
- PDF p77、p83、p86 等处体现用低级别寻找更精确买点或短差机会。

验收标准：

- 支持从高级别信号下钻到次级别确认。
- 输出区间套路径，例如日线信号 -> 30 分钟确认 -> 5 分钟精确点。
- 不同级别信号冲突时，提示所属级别和适用操作周期。

## 11. 操作辅助体系

### F21. 持股与持币状态

功能描述：

- 根据买卖点、走势类型和级别关系，输出持股、持币或观望状态。

需求依据：

- PDF 目录包含“持股与持币，两种最基本的操作”。
- PDF 多处强调根据买卖点和级别进行操作，而不是追涨杀跌。

验收标准：

- 状态建议必须附带结构依据。
- 不输出收益承诺。
- 同时存在多级别信号时，应区分短线、中线、长线状态。

### F22. 短差辅助

功能描述：

- 对已在大级别买点介入的用户，提示次级别卖点减仓和次级别买点回补。

需求依据：

- PDF p83、p86-p87 描述大级别买点介入后，可利用次级别第一类卖点和买点做短差。

验收标准：

- 必须标明短差基于哪个大级别持仓背景。
- 不把次级别短差信号误标为大级别趋势反转。

### F23. 风险退出

功能描述：

- 当买入或卖出程序的前提被破坏时，提示退出或信号失效。

需求依据：

- PDF p74-p75 说明买入程序一旦基础条件被破坏，应退出。

验收标准：

- 每个买卖点信号应维护失效条件。
- 失效后输出风险提示，而不是继续保持原信号。

## 12. 功能优先级

P0：基础结构

- K 线包含处理。
- 分型识别。
- 笔识别。
- 线段识别。
- 中枢识别。

P1：走势与级别

- 中枢指标。
- 中枢延伸、扩展、新生。
- 走势类型识别。
- 走势终完美。
- 级别递归。

P2：交易辅助

- 第一、第二、第三类买卖点。
- 背驰与 MACD 辅助。
- 盘整背驰。
- 同级别分解。
- 区间套。

P3：操作体验

- 持股持币状态。
- 短差辅助。
- 风险退出。
- 多级别信号解释。

## 13. 总体验收标准

- 所有结构必须标明级别。
- 所有买卖点必须标明所属结构和失效条件。
- 所有背驰必须标明比较对象。
- 任何中枢、走势、买卖点均不得依赖未来数据。
- 同一份已完成行情数据应输出稳定、可复现的结构结果。
- 系统应区分“已确认”“候选”“失效”三类状态。
